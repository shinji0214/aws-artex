## 1本目: AIペンテストツール ARTEX を自作AWS環境で動かしてみた

**想定読者:** AWSは触ったことがあり、AIペンテスターが実際どう動くのか知りたい人
**ゴール:** 構成・コスト・ARTEXの探索の様子が分かる

1. **はじめに**
   - 動機（攻撃者視点と防御側ログの両方を学びたい）
   - ⚠ 免責: 対象は自己所有環境の OWASP Juice Shop のみ。第三者への実行は不正アクセスになり得る
2. **全体構成** — 構成図（P1-1）、なぜ ALB 無しの EC2 直構成にしたか
3. **事前準備: admin を使わない IAM** — P0-1, P0-2, P0-3
   - ハマりどころ: instance-profile / PassRole 不足（P0-4）
4. **Terraform で環境構築** — P1-2, P1-3, P1-4
   - SG を `/32` に絞る理由（P1-5）
   - ログの仕込み（Flow Logs / CloudTrail / アプリログ → P1-6〜P1-8）
   - コラム: Fargate で vCPU 上限に当たって EC2 に切り替えた話（P1-9）
5. **ARTEX のセットアップ** — P2-1〜P2-4
   - APIキー必須（サブスクでは動かない）、既定モデルが高いので Haiku に変更
6. **ARTEX を走らせてみた** — 記事のメイン
   - Planner の最初の計画（P2-6）
   - Worker の動き・API探索（P2-7, P2-8）
   - Asset Graph / Exploration Graph の変化（P2-9, P2-10。GIF推奨）
   - 面白かった判断・失敗（P2-11）
   - 結果（P2-12）
7. **かかったお金** — AWS（時間課金・destroy運用）＋ LLM トークン（P2-13）
8. **まとめと次回予告** — 「この探索、AWS側からはどう見えていたのか？」→ 2本目へ
9. 片付け（P1-10）／リポジトリへのリンク
